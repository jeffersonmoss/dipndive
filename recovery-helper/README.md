# Mac recovery and repair

Version 1.4 adds a full-width **Recover iMac** button below the existing five-button row. It appears only on Mac after a summary attempt fails with no summary loaded. In that state, the left outer arrow opens an interactive Claude Code repair chat; the right opens an interactive Codex repair chat. A completed summary restores the existing Claude/ChatGPT transcript handoff and hides recovery. Windows keeps its existing handoff behavior.

1. Install with `/usr/bin/python3 recovery-helper/install_mac.py` from this repository, then reload the extension yourself.
2. On the first recovery or repair click, allow Chrome to communicate with the installed native helper. This optional permission is requested only in that click.
3. **Recover iMac** opens Terminal, checks the companion, discovers the iMac address through Thing One if needed, and offers ordinary password SSH and Screen Sharing. FileVault unlock, SSH login, Screen Sharing authentication, and desktop login are separate steps. An SSH disconnect after FileVault unlock is expected. You may need to enter the password again for the post-login reconnect. Keep passwords in those OS windows.
4. After desktop login, the helper attempts to reconnect the existing Tailscale profile and start the companion. It does not restart a running companion. It verifies reachability and asks you to retry the Dip. If it cannot finish, it offers interactive Codex repair in Terminal. The arrows can launch repair directly for caption, acquisition, model, or other failures.
5. Close or interrupt recovery to cancel. Password SSH times out after 180 seconds; desktop recovery after 10 minutes; an interactive repair chat after 60 minutes. Owned SSH tunnels and local child processes are stopped in `finally`. A disconnected remote post-login waiter is bounded to 10 minutes. No permanent monitor, daemon, password storage, FileVault change, host-key bypass, or Chrome automation is installed.

The native host accepts only status, fixed-target recovery, or a whitelisted Claude/Codex repair launch. Its manifest restricts the extension origin. IPC contains only failed URL, error, mode, job ID, and version; the host removes URL credentials and secret query parameters and redacts bearer credentials before preparing the repair prompt. No transcript, conversation thread, extension token/configuration, or password is included. Repair chats use the existing subscription CLI and normal sandbox/approval settings. Their histories remain ordinary user-owned chats.

The helper lives in `~/Library/Application Support/DipDive Recovery`; Chrome registration is `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.jeffersonmoss.dipdive_recovery.json`. Status and launch-context files remain there for recovery continuity, mode 0600. The directory is mode 0700. Existing helper upgrades retain a rollback under a dated `~/dipndive/Recovery helper before update` folder; existing rollback folders are never overwritten. Extension rollback copies are preserved separately before deployment.

From Thing Two, Thing One must be online and reachable over its existing SSH route when the iMac is offline on Tailscale. On Thing One, recovery uses its home LAN directly; on the iMac, recovery uses local commands. Neither needs an SSH-to-itself or iMac-to-gateway key. The helper discovers the home-LAN address each run. It never opens a router port or weakens SSH/TLS verification. The helper uses its own pinned public host keys for the two already-verified recovery hosts; it does not edit global SSH trust or grant new login access. A changed host key stops recovery until independently verified. A powered-off iMac, lost home internet, unavailable gateway, changed credentials, or unknown host key needs owner attention. Recovery is intended to restore access, not promise unattended FileVault unlock. Model sign-in/isolation and a real completed Dip are separate acceptance checks.

Checks: `node --test extension/test/*.test.mjs`; `/usr/bin/python3 -m unittest discover -s recovery-helper -p 'test_*.py'`. Run the latter in a deletion sandbox permitting cleanup only in throwaway `/private/tmp` folders. Native protocol status can be tested without launching any agent or changing the iMac. Do not force a reboot or logout merely to test recovery while Jefferson is away.

Disposable consultation/review output is registered under `dipdive-recovery-button-november-build` in the external-model retention store; substantive instructions and this implementation are retained here.
