# dipdive

PoC 1 of the Dip & Dive companion: acquisition (plan 3.3), isolated model calls (3.4) and prompts (3.5) as an importable Python module, plus a CLI. Plan: `CODEX PROJECTS/DIP_DIVE/PLAN.md` (see POINTER.md there).

## Use

    .venv/bin/python -m dipdive <url> <claude-dip|claude-dive|codex-dip|codex-dive|source>

Prints the summary, or `ERROR <code>: <message>` on stderr with exit status 1. The later HTTP server imports `dipdive.cli.run_job(url, mode)`, `dipdive.acquire.acquire(url)` and `dipdive.models.call_model(...)`.

## Server (plan 3.2, Stage A)

    .venv/bin/python -m dipdive.server [port]     # default 8765, binds 127.0.0.1 only

Files: `dipdive/service.py` (job store, source cache, workers, health), `dipdive/server.py` (HTTP, auth). State lives in `~/Library/Application Support/DipDive/` (override with `DIPDIVE_SUPPORT`): `jobs/`, `sources/`, `results/`, `logs/`, `state.json` (clear generation), `token` (0600, created on first start, never printed). Requests need `Authorization: Bearer <token>`; requests with a web-page `Origin` or a non-loopback, non-`*.ts.net` Host are refused; there is no CORS.

Endpoints: `POST /jobs {url, mode, requestId, force?, question?, history?, summary?, clearGeneration?}` (202 new, 200 existing, 409 `request_id_conflict` or `stale_clear_generation`, 429 `queue_full`), `GET /jobs/{id}`, `GET /source?job=<id>` (cache only, never fetches), `POST /clear`, `GET /health`. `clearGeneration` (optional integer) is the clear generation the client last saw (every answer and `/health` carry the current one). One older than the companion's own is refused with 409 `stale_clear_generation` (the body carries the current `clear_generation`) before anything else happens: no job, no fetch, no model call, nothing stored, and the `requestId` is not remembered. It means another machine pressed Clear history after the client's summary and question thread were built, so they no longer belong to the companion's history. A client that has seen no generation yet leaves the field out; one that is ahead of the companion (the state file was lost) is served, and the lower generation in the answer tells it so. A value that is not a non-negative integer is a 400. Dedupe key is sha256 of normalized source id, mode, model id and prompt version (plus a hash of the question, history and summary for the ask modes); the result cache additionally includes a hash of the source text.

Ask modes (`claude-ask`, `codex-ask`, `dipdive/ask.py`): `question` (required, at most 2000 characters, whitespace collapsed), optional `history` (`[{"q","a"}, ...]`, oldest first) and optional `summary` (the Dip or Dive text the panel is showing; the first 4000 characters are kept). Every limit and the emptiness check apply to the normalized text (NFKC, invisible and default-ignorable characters removed, lone surrogates replaced by U+FFFD), which is what reaches the model, so a character that NFKC expands cannot get past a limit and a question of only zero-width characters is refused; text the JSON carries that cannot be UTF-8 encoded is repaired, never a 500. The companion keeps the newest 6 turns, clips one earlier question to 500 and one earlier answer to 3000 characters, then drops the oldest turns until at most 8000 characters remain; the cache key hashes the question, that capped history and the summary, so what the panel trimmed never changes the key. Same isolated model call as Dip and Dive (same Claude and Codex flags, 45 s limit, Codex at low effort), same source cache and coalescing, same `requestId` idempotency (a reused `requestId` with another question is 409). The question, the summary, every earlier turn and the source are neutralized against the `<source>`, `<summary>`, `<history>`, `<turn>`, `<asked>`, `<answered>` and `<question>` delimiters (look-alikes, entity and percent forms, and every default-ignorable character are handled); each earlier turn sits in its own `<turn>` block, so an answer that quotes `Q: ...` lines cannot pass for a user question; the source, the summary and the earlier answers stay untrusted data and only `<question>` and `<asked>` are the user's own words. The prompt asks for at most about five sentences, a plain "the source does not cover that" when it does not, no invention, and one short sentence naming the possibilities when a reference such as "the second one" cannot be resolved. `question`, `history` or `summary` on a non-ask mode is a 400. `PROMPT_VERSION` is `p4` (p3 added the ask prompt; every bump invalidates cached Dip and Dive results once).

History log (`dipdive/historylog.py`): every time a Dip or Dive job (`claude-dip`, `claude-dive`, `codex-dip`, `codex-dive`) finishes successfully, one Markdown entry is appended to a durable log. Default `~/Public/Dip'n'Dive Log.md` (the iMac's shared Public folder, readable from other machines); set `DIPDIVE_LOG_PATH` to move it. The file is created with a one-line heading if missing. Newest entries are at the bottom; each is a `## <title>` heading, a line `YYYY-MM-DD HH:MM | Claude Dip | [url](<url>)` (local time, mode label, link), the summary exactly as shown, a blank line and `---`. Not logged: asks, `source` jobs, errors, and results served from the result cache or by deduplication (a job is logged only when a model call just produced its text; a forced re-run is a new result and is logged, and so is the same video summarized again after Clear history, because the result cache is gone by then). A job that is cleared while it runs is not logged. Appends take a thread lock and an advisory file lock and go out as one write, so two jobs finishing together leave two intact entries. The only edits to the summary are a line made only of hyphens (a rule) gaining a leading backslash so it cannot pass for the separator, and a code fence left open being closed. A log failure never fails the job: the error is written to the job log (`logs/`, key `history_log_error`). **Clear history (`POST /clear`) does not touch this log**; it is deliberately outside the support folder, and deleting it is a manual act. `GET /health` carries `log_path` and `log_writable` (checked live, touches nothing).

iMac deployment (written, not loaded anywhere): `deploy/install-imac.sh [--dry-run] [--port N]` renders `deploy/com.jeffersonmoss.dipdive.plist.template` (RunAtLoad, KeepAlive, ThrottleInterval 10, explicit PATH, `DIPDIVE_DENO`), bootstraps it into the GUI session, and runs `tailscale serve --bg --https=443`. It prints the `pmset` command (needs sudo, run by hand).

## Codex home notes

The module creates `~/Library/Application Support/DipDive/codex-home` and its config.toml. The settings that matter are also passed as `-c` and `--disable` flags on every call, because `--ignore-user-config` makes config.toml dead. Codex still writes plugin clones (`.tmp/`), `skills/`, `memories_1.sqlite`, `goals_1.sqlite`, `state_*.sqlite` and logs into that home; they do not matter for isolation (the features that use them are disabled, and any tool item in the event stream kills the call). The module prunes `.tmp` and `shell_snapshots` entries older than a day.

Test-only hook: `DIPDIVE_TEST_ALLOW_LOOPBACK=1` lets the fetch worker reach 127.0.0.1 (used by tests/test_regressions.py). Never set it in production.

### The five buttons

Five large square buttons, left to right: Claude Dive, Claude Dip, Temp chat, Codex Dip, Codex Dive. The shallowest immersion (Temp chat) is in the center and the water gets deeper toward both edges. Colors: Claude Dip pale orange, Claude Dive the Claude orange `#D97757`, Codex Dip pale blue, Codex Dive full blue, Temp chat white or neutral; the Dip squares stay pale in dark mode too. The pressed button looks physically pressed in (inset, shifted down, darker edge); there are no radio buttons. The buttons are created from one ordered list (`MODES` in `lib/modes.js`) and nothing reorders them, so the Tab order is the same left to right.

### Question box and microphone (mouse only)

Below the result the panel has a box ("Ask a question"), a mic button and an Ask button. These controls are docked at the bottom of the panel: everything else (summary, thread, status) scrolls above them, and every message line (listening, errors, Enable microphone) grows upward from them, so nothing arriving while the person talks can move the mic button between the click that starts a recording and the click that stops it. Typing and Enter, or the Ask button, send the question. The mic is click to start, click again to stop: the button turns red and says Stop, the words appear in the box as they are recognized, and the second click sends the text automatically. Everything is reachable with the mouse. The previous questions and answers in this panel for this source (newest 6 turns, 8000 characters) and the Dip or Dive text on screen (first 4000 characters) go along with each question, so follow-ups work ("and why?", "tell me more about the second one"). Each earlier turn is sent in its own `<turn>` block and the summary in `<summary>`; they and the source are data, never instructions. The thread is forgotten when the source changes (another link, typed or right-clicked; the same video written another way keeps it), on Clear history (in this window or in any other window: the other panels learn of it through a `clearGen` storage key and also from the generation number in the companion's answers). Clear history on another machine cannot reach this browser's storage, so every `POST /jobs` (summary, Temp chat and question) carries the clear generation the panel knows (`clearGeneration`, left out until the panel has heard one). If the companion answers 409 `stale_clear_generation`, the panel forgets its thread and summary, adopts the companion's generation, shows "History was cleared on another machine." (in the page for a button press, next to the question box for a question, which goes back into the box), and sends nothing again by itself: the next press or Ask is the person's own and carries the new generation. A link from a right-click or Go that was refused is dropped from storage so reopening the panel does not submit it later, and when the panel closes. The provider follows the pressed button: Claude Dive and Dip ask Claude, Codex Dip and Dive ask Codex, Temp chat asks Codex unless `/health` says Codex is unavailable (then Claude).

Speech recognition is Chrome's built-in `webkitSpeechRecognition` (English, interim results, continuous mode), running in the side panel page itself. Chrome ends a continuous session by itself after about 15 seconds of silence (8 seconds if nothing is said at the start); when that happens, or when the panel is hidden, the recognized words are kept in the box and are not sent, with one line saying so, so a long pause never sends half a question. Words typed in the box before the mic is clicked stay, and the spoken words are added after them; Chrome sends the audio to Google's speech service. A side panel cannot show Chrome's microphone prompt, so the panel checks `navigator.permissions` for the microphone and, when it is not granted, shows an Enable microphone button. That opens `mic.html` in a normal tab, which calls `getUserMedia({audio:true})`, stops the tracks and tells the user to go back to the panel (the button to click in Chrome's prompt is "Allow while visiting the site", not "Allow this time"). If the computer itself blocks the microphone for Chrome (macOS Privacy and Security, Windows privacy switches), both the tab and the panel say so and name the setting instead of looping through the prompt. No offscreen document and no extra manifest permission are needed (evidence in RESULTS section 13). Real-Chrome checks (throwaway Chrome profile, never the real one, everything removed on exit): `node tests/chrome/speech-probe.mjs [--headed --side-panel] [--no-grant]` for the recognizer, `node tests/chrome/panel-e2e.mjs` for the real panel, `mic.html` and the permission flow against the dev harness. Live Claude check of the ask modes: `.venv/bin/python -m tests.e2e_ask` (3 Haiku calls). Dev harness: add `&mic=granted|prompt|denied|none&say=words` to the panel URL for a scripted recognizer and fake permission state (`window.__devMicGrant()` simulates Allow).
